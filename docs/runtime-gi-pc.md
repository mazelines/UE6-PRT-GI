# 동적 GI 전환: PC 기준 구현

작업 브랜치는 `feat/runtime-surfel-gi`이다. 목표는 **PC에서 동작·품질·갱신 비용을 검증한 뒤 모바일로 확장**하는 것이다. 방 꾸미기처럼 가구 배치가 달라지는 장면에서, 완성된 레벨의 광전달 행렬을 다시 굽지 않고 간접광을 갱신하는 경로를 먼저 만든다.

설계 기준은 사용자가 공유한 **Love and Deepspace GDC 2026 정리 문서**의 에셋별 표면 준비와 런타임 광전달 분리다. 현재 구현은 그 전환을 검증하는 **삼각형 BVH 기반 GPU 경로 추적 기준 구현**이다. 문서의 디스크 Surfel 추적이나 Radiance Cascade를 구현했다고 볼 수 없으며, 문서에 나온 모바일 성능 수치를 이 코드에 적용해서도 안 된다.

## 현재 경로

1. `PRTGI.Runtime.Prepare`가 메시 LOD0와 재질 조합별 표면 데이터를 준비한다. 기존 재질 베이커를 에셋 로컬 공간에서 사용하고, 삼각형별 반사율·접선 공간 법선을 8×8 차트로 보관한다. 같은 메시와 재질을 쓰는 가구는 이를 공유한다. 현재 캐시는 메모리에만 있으며 에디터 세션마다 준비한다.
2. 0.25초 간격으로 메시·재질 식별자, 인스턴스 변환, 가시성, 그림자 설정, 광원, 프로브 배치를 확인한다. Static/Movable 메시와 ISM/HISM 인스턴스를 수집한다. `PRTGI.Ignore` 컴포넌트 태그로 제외할 수 있다.
3. 변경 시 현재 인스턴스 변환으로 삼각형 BVH를 만든다. 월드 공간 재질 차트는 메시·재질·변환별로 재사용하므로, 가구 하나를 움직일 때 다른 인스턴스의 차트를 다시 변환하지 않는다. 현재 장면에서 쓰지 않는 변환 캐시는 제거한다. 레벨 전체의 PRT 전송 항목을 생성하거나 저장하지 않는다. CPU 스냅숏 시간은 상태 로그에 별도로 기록한다.
4. GPU가 프로브에서 결정적인 구면 방향으로 광선을 쏘고, 충돌 표면에서 직접광을 평가한다. 이후 코사인 가중 반구 방향으로 경로를 이어 간접 반사를 계산한다. 기본 6회, 최대 12회이며, 처음 4회 이후 누적 반사율 최댓값이 0.01보다 작은 경로는 종료한다. 이는 편향된 근사다.
5. 입사 radiance를 SH9에 투영하고 각 밴드에 코사인 커널을 한 번 적용해 irradiance로 저장한다. 최종 수신 표면의 반사율/π 적용은 기존 resolve가 담당한다. 프로브 첫 교차의 뒷면 비율이 25%를 넘으면 해당 프로브를 제외한다.
6. GPU 작업은 프로브 단위 배치로 나눈다. 동시에 한 배치만 진행하며, 마지막에 SH를 CPU로 읽어 전체 세대 결과를 게시한다. 계산 도중 장면이 다시 바뀌면 이전 작업의 결과는 게시하지 않는다. 변경 시 기존 GI를 비우므로 새 결과가 완성될 때까지 간접광이 잠시 사라질 수 있다.
7. resolve의 프로브 가시성과 접촉 차폐에는 현재 BVH를 사용한다. 런타임 프로브의 이진 가시성은 차폐물을 하나 찾으면 탐색을 종료한다. 접촉 차폐에는 여전히 가장 가까운 교차 거리를 사용한다. 장면이 정지하면 광전달 갱신은 멈추지만, 화면 resolve와 가시성 검사 비용은 매 프레임 발생한다. 선택 옵션으로 동일 프레임의 반해상도 간접광을 재구성할 수 있다.

## 실행

UE6 Win64 Development Editor, DX12/SM6, 디퍼드 렌더링에서 사용한다. 레벨에 활성화된 `PRTProbeVolume`이 있어야 한다. 이 경로에서는 볼륨의 범위·간격을 사용하며 **Build Precomputation은 필요하지 않다**.

```text
PRTGI.Runtime.Prepare
PRTGI.SetMode PRT
r.PRTGI.Runtime 1
PRTGI.Runtime.Status
```

에셋 준비를 마친 메시·재질 조합은 이동·회전·크기 변경·복제·삭제 시 재준비하지 않는다. 새로운 메시나 재질 조합을 도입하거나 재질을 편집하면 `PRTGI.Runtime.Prepare`를 다시 실행한다. 아직 준비하지 않은 에셋은 상태의 `Error`로 알리고 GI 게시를 중단한다. 기존 정적 PRT로 돌아가려면 `r.PRTGI.Runtime 0`을 실행한다. 정적 경로에는 기존 사전 계산 캐시가 필요하다.

같은 에디터 프로세스에서 PIE로 들어갈 때는 준비한 에셋 데이터를 유지하고 월드의 조명 결과만 새로 계산한다. PIE 중 변환 변경은 게임 월드에 반영되며, PIE 종료 후에는 에디터 월드의 배치를 기준으로 다시 갱신한다.

| 설정·명령 | 기본값 / 의미 |
|---|---|
| `r.PRTGI.Runtime` | 0. 실험 경로는 명시적으로 활성화 |
| `r.PRTGI.Runtime.Rays` | 프로브당 256, 범위 64~1024 |
| `r.PRTGI.Runtime.Bounces` | 6, 범위 1~12 |
| `r.PRTGI.Runtime.ProbesPerBatch` | 32, 범위 1~256. GPU 시간 예산 자체는 아님 |
| `r.PRTGI.Runtime.VisibilityAnyHit` | 1. 런타임 프로브 차폐물을 찾으면 즉시 종료. 0은 가장 가까운 교차를 찾는 비교 경로 |
| `r.PRTGI.Runtime.ResolveHalfResolution` | 0. 1은 런타임 간접광을 가로·세로 절반 해상도로 계산하고 조건에 맞는 표면에서 재구성. 디버그 표시에는 적용하지 않음 |
| `PRTGI.Runtime.Status` | 에셋 준비 횟수, 세대, 폐기 작업, 변환 차트 갱신 수(`ChartUpdates`), CPU 스냅숏 시간, 게시 대기 여부, 수렴 시간 |
| `PRTGI.Runtime.Dump` | `Saved/PRTGIRuntime/probes.csv`에 게시된 SH와 유효성 기록 |
| `r.PRTGI.Runtime.SurfelPool` | 0. 1은 기준 조명과 함께 GPU 표면 풀·공간 인덱스를 갱신. 아직 조명 출력에 사용하지 않음 |
| `r.PRTGI.Runtime.SurfelSeedSpacingCm` | 50cm, 범위 1~1000. 에셋 로컬 삼각형 분할 기준. 변경 후 `PRTGI.Runtime.Prepare` 재실행 |
| `PRTGI.Runtime.Surfels.Validate` | GPU 풀·셀 목록·주변 조회를 CPU 계산과 대조. 결과는 상태 로그와 `Saved/PRTGIRuntime/surfel-audit.txt`에 기록 |

`ConvergenceSeconds`는 여러 프레임에 걸친 전체 갱신 지연이다. GPU 패스 시간이나 프레임 시간과 구분한다. PC 기준 구현의 안전한 작업 크기 제한은 총 32,768 프로브와 100,000 삼각형이다. 제한을 넘기면 자동으로 해상도를 낮추지 않고 오류를 보고한다.

## PC 검증 결과 — 2026-11-03

UE6 Win64 Development Editor, DX12/SM6, RTX 4090, i9-14900KF에서 검증했다. Showcase의 전체 지오메트리 53개 인스턴스·11,400개 삼각형을 사용하고, 조명 계산은 ClassicBox의 512개 프로브로 제한했다. 프로브당 256개 광선, 최대 6회 반사, 배치당 32개 프로브이다. 수치는 개별 관측값이며 여러 번 반복한 성능 통계가 아니다. 원시 수치와 테스트 목록은 [검증 보고서](../Plugins/PRTGI/Tools/validation_runtime_pc.json)에 있다.

화면 resolve 비용이 여전히 크다. 특히 현재 프레임의 BVH로 최대 64개 프로브의 가시성을 검사하는 경로는 모바일에 그대로 가져갈 수 없다. 후속 최적화에서는 이 기준 결과를 보존하고 런타임 프로브 가시성 캐시, 적은 보간 표본 수, 저해상도 resolve와 업샘플을 비교해야 한다. 최초 월드 구성과 새 고밀도 메시의 변환 비용도 별도로 측정해야 한다.

GPU 해석 검사는 `Automation RunTests PRTGI.Runtime.AnalyticHemisphere`로 실행한다. 전체 관련 검사는 `Automation RunTests PRTGI.`이다. 로컬 프로젝트의 기존 CommonUI 뷰포트 검사는 테스트 중에만 비활성화하고 복원했다. 엔진 전체나 EditorToolset 전체 테스트의 통과를 의미하지 않는다.

## 화면 합성 최적화 실험 — 2026-11-03

`r.PRTGI.Runtime.ResolveHalfResolution 1`은 프로브 보간과 BVH 가시성 검사를 가로·세로 절반 해상도에서 수행한다. 최종 픽셀은 주변 네 표본이 같은 볼륨에 속하고, 법선 내적이 0.9995 이상이며, 두 접평면의 오차가 0.1cm 이하이고, 표본 간 거리가 최소 프로브 간격의 10% 이내일 때만 보간한다. 하나라도 조건을 벗어나면 그 픽셀에서 원래 해상도로 다시 계산한다. 선택 볼륨의 간접광만 재구성하며, 겹치는 볼륨의 경계 블렌딩은 기존 계산을 유지한다.

재질 색상·금속성·GGX 에너지 보정과 접촉 차폐는 기존 최종 픽셀에서 적용한다. 조명 버퍼는 노출 적용 전 FP32 irradiance를 저장해 밝은 광원에서 FP16 범위를 넘는 문제를 피한다. 이전 프레임의 버퍼를 사용하지 않는다. 3309×1508에서는 추가 임시 버퍼가 약 19.0MiB 필요하다. 이는 프로브 가시성 캐시나 Radiance Cascade가 아니라 화면 합성 단계의 공간적 근사다.

RTX 4090 / i9-14900KF, UE6 Win64 Development Editor, DX12/SM6에서 세 모드를 번갈아 5회 측정했다. 에디터 화면 비율은 100%, 뷰포트는 3309×1508, AA와 접촉 차폐는 끄고 간접광만 표시했다. ClassicBox·ColorBox 두 볼륨의 1,664개 프로브, 전체 11,400개 삼각형, 프로브당 256광선·최대 6바운스다. 아래 시간은 광전달 갱신이 끝난 뒤 **화면 합성 패스 합계의 중앙값**이며 전체 프레임 시간이나 광전달 갱신 시간이 아니다.

| 시점 | 가장 가까운 교차 / 전체 해상도 | 첫 차폐물 종료 / 전체 해상도 | 첫 차폐물 종료 / 반해상도 |
|---|---:|---:|---:|
| 원경 | 7.119ms | 7.127ms | 8.865ms |
| 구체 근접 | 57.970ms | 53.614ms | 18.151ms |

근접 화면에서는 반해상도가 기준 대비 약 69% 빨랐지만 원경에서는 약 25% 느렸다. 따라서 **반해상도 기본값은 0을 유지**한다. 첫 차폐물 종료도 모든 시점에서 성능 이득을 보장하지 않는다. 카메라와 표면 구성에 따른 비용 차이가 크므로 이 수치를 게임 전체의 성능으로 일반화하지 않는다. 이전 절의 측정은 볼륨 수·화면 비율·접촉 차폐 조건이 달라 직접 비교할 수 없다.

1399×789의 홀수 해상도에서 선형 HDR을 비교했다. 첫 차폐물 종료는 원경·구체 근접에서 기준 캡처와 픽셀 차이가 0이었다. 반해상도의 전체 화면 RGB 상대 RMSE는 각각 약 0.164%, 0.215%였다. 같은 기준 경로의 반복 캡처에도 각각 약 0.052%, 0.131% 차이가 있으므로 작은 차이 전부를 이 변경의 오차로 해석하지 않는다. 전체 화면 수치는 국소 윤곽선의 오차 상한을 의미하지 않는다. 구체를 25cm 이동한 상태와 접촉 광선 8개를 켠 상태도 별도로 비교했다. 원시 측정·카메라·설정·검증 목록은 [합성 검증 보고서](../Plugins/PRTGI/Tools/validation_runtime_resolve.json)에 기록했다.

## GPU Surfel 풀과 공간 조회 — 2026-11-03

Webgiya 검토 후 첫 단계로 **에셋 표본 공유와 인스턴스별 GPU 표면 관리**를 추가했다. 풀에는 위치·법선·반사율·소유권만 있으며 irradiance는 없다. 옵션을 켜도 조명은 기존 삼각형 BVH 기준 경로에서 계산한다. 조명 품질이나 성능 개선이 완료된 단계는 아니다.

```text
PRTGI.Runtime.Prepare
PRTGI.SetMode PRT
r.PRTGI.Runtime 1
r.PRTGI.Runtime.SurfelPool 1
PRTGI.Runtime.Status
PRTGI.Runtime.Surfels.Validate
```

활성화된 유효 `PRTProbeVolume`이 필요하다. `SurfelError`가 비어 있고 `SurfelLive`가 생성됐는지 확인한 뒤 검사를 실행한다. 검사는 요청할 때만 전체 GPU 데이터를 읽는다. `SurfelAudit=PASS`의 `Revision`은 요청 당시의 스냅숏이며 `CurrentRevision`과 다르면 그 사이 장면이 갱신된 것이다. `SurfelUpdated`와 `SurfelRetired`는 마지막 표면 변경에서 갱신·반환한 인스턴스 범위 수다. 정지 중에는 마지막 수치를 유지한다.

### 표본 생성과 소유권

각 삼각형을 최장 변과 로컬 간격에 따라 균등 분할하고, 작은 삼각형마다 중심 표본 하나를 만든다. 기존 8×8 재질 차트에서 반사율과 셰이딩 법선을 읽는다. 로컬 표본은 위치·셰이딩 법선·중심 상대 꼭짓점 두 개·반사율·기하 법선의 6개 `float4`, 즉 96B다. 같은 메시·재질 조합을 사용하는 인스턴스가 공유한다. 세 번째 상대 꼭짓점은 앞의 두 벡터 합의 음수로 복원한다.

월드 풀은 표본당 64B다. GPU에서 인스턴스 변환과 역전치 법선 변환을 적용하고, 변환된 꼭짓점을 포함하는 지지 구의 반경을 계산한다. 음수·비균일 스케일을 지원하지만 밀도는 에셋 로컬 기준이므로 확대하면 월드 표본 간격도 커진다. 월드 밀도에 따른 재분할이나 LOD는 아직 없다. 현재 조회는 지지 구 포함 검사이며 디스크 교차나 조명 보간 가중치가 아니다.

컴포넌트는 UObject 생성 일련번호를 포함한 `FObjectKey`로 구분한다. ISM/HISM은 UE의 `FSMInstanceElementIdMap`을 함께 사용해 앞쪽 인스턴스 삭제로 배열 번호가 바뀌어도 남은 인스턴스의 소유권을 유지한다. 움직인 인스턴스의 슬롯 범위만 변환하고, 삭제된 범위는 0으로 지운 뒤 반환한다. 복제는 로컬 에셋 버퍼를 공유하면서 새 슬롯 범위를 받는다. 풀 비활성화나 월드 전환 시 월드 풀은 다시 구성한다.

기본 용량은 65,536개, 해시 버킷은 16,384개다. 풀 4MiB, 셀 키 1MiB, 슬롯 목록 0.25MiB, 오프셋 약 0.0625MiB로 **주요 상주 버퍼 합계 약 5.31MiB**다. 에셋 로컬 버퍼, 임시 스캔 버퍼, 감사용 읽기 버퍼는 제외한 배열 크기 합계이며 GPU 메모리 실측값이 아니다. 연속 슬롯 할당이므로 빈 슬롯 합계가 충분해도 단편화로 실패할 수 있다. 용량 초과·잘못된 변환·지원 범위 초과는 `SurfelError`로 보고하고 직전 유효 풀을 보존한다. 오류 상태의 풀은 현재 장면과 일치한다고 간주하면 안 된다.

### 공간 인덱스와 검증

기본 셀 폭은 32cm다. 표본 반경의 두 배를 담는 레벨을 16단계 중 선택하고, 중심을 해당 레벨의 셀 하나에 넣는다. GPU에서 **개수 계산 → 블록별 누적 합 → 블록 오프셋 합산 → 슬롯 배치** 순서로 버킷별 연속 목록을 만든다. 해시 충돌은 정확한 정수 셀 좌표와 레벨을 다시 비교해 제외한다. 셀마다 앞의 몇 개만 읽는 절단은 없다. 검증용 조회는 각 레벨의 주변 27개 셀을 확인한다. 이는 정확성 비교용이며 최종 화면 합성에 맞춰 최적화한 조회가 아니다.

지오메트리가 바뀌면 셀 목록 전체를 다시 만든다. 광원만 바뀌거나 변환이 같으면 표면 풀 세대를 올리지 않는다. CPU 소유권 대조와 전체 셀 재구성 비용은 후속 최적화 대상이다. 현재 월드 좌표는 각 축 ±200,000m, 지지 반경은 기본 셀 폭의 16,384배 이내로 제한한다. 삼각형 한 변의 분할 수는 최대 32, 에셋 표본은 최대 1,048,576개이며 풀 용량 제한은 별도로 적용된다.

UE6 Win64 Development Editor / DX12·SM6, RTX 4090에서 아래를 확인했다. 조명 비교에는 ClassicBox 512개 프로브와 전체 Showcase 지오메트리를 사용했다. [원시 상태·검증 목록](../Plugins/PRTGI/Tools/validation_runtime_surfel_pool.json)에 결과를 기록했다.

## 지원 범위와 남은 작업

현재 지원하는 것은 불투명 정적 메시 자산의 인스턴스 변환과 방향광·역제곱 감쇠 포인트 라이트다. 메시의 Mobility는 Movable이어도 된다. 포인트 라이트 밝기는 UE의 단위 변환을 사용하고 cm를 m로 환산한다. 광원의 색온도와 간접광 강도를 반영한다.

현재 제외되는 것은 스키닝, WPO, 시간·월드 위치·인스턴스별 입력에 의존하는 재질, MID와 런타임 재질 파라미터 변경, 정점 페인팅, masked/translucent, 스포트·렉트·하늘광, 발광 전송, 정반사 GI다. 재질 차트는 유한 해상도의 근사이며 원본 텍스처 해상도를 보장하지 않는다. 에셋의 불투명 표면과 UV 기반 재질을 사용해 검증한다.

이 단계에는 에셋 캐시의 디스크 직렬화·쿠킹, 자동 프로브 clipmap, 국소 프로브 무효화, Surfel LOD, GPU BVH 갱신, Radiance Cascade 방향 병합, 시간 누적·노이즈 제거, 모바일 fallback이 없다. Surfel 공간 해시는 위의 선택적 표면 풀에만 적용된다. CPU의 전체 장면 BVH 재구성과 차트 배열 병합, SH 읽기, 픽셀별 BVH 가시성은 정확도 비교를 쉽게 하기 위한 기준 경로이며 최종 성능 구조가 아니다.

후속 구현은 같은 배치·광원 변경 시나리오의 기준 SH와 화면을 보존한 상태에서 진행한다. [Webgiya 적용안](webgiya-surfel-cache-review.md)의 첫 단계인 GPU 표면 풀·공간 인덱스 검증을 마쳤다. 다음은 별도 GPU irradiance 버퍼와 반복 조명 갱신이다. 기존 삼각형 BVH를 비교 기준으로 유지하고 조명 단위·수렴·이동 후 무효화를 먼저 확인한다. 조회용 방향별 가시성 캐시와 시간 필터, 자동 clipmap·Radiance Cascade와 모바일 확장은 이후 단계다. PC에서 GPU 갱신·resolve 시간과 CPU 지연을 분리 측정한 뒤 모바일의 메모리·정밀도·대역폭·저사양 fallback을 검증한다.
